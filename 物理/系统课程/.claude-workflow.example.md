### 核心原则速记
| 原则 | 一句话 |
|------|--------|
| 双讲义输出 | 每次同时创建学生版 + 教师版 |
| 大题规范 | {{科目特有答题格式}} |
| 思考框架 | 读题→分析→规划→执行→验证，每道题都要先想清楚再动笔 |
| 严格标准 | 不因自学降低要求，按正式课堂标准要求学生 |
| 查漏补缺 | 优先发现自学中的知识漏洞，而非按教材顺序推进 |
| 答案格式 | {{考试标准答题格式}} |
| 系统课程 | 金标准：教材+课标+学科史，辅以参考教辅。系统全面有深度，不依赖学生个性 |
| 学生版讲义 | 零 AI 味 meta。根据学生错题+需求定制，难度根据交互不断更新 |
| 教师版讲义 | 口语化、黑板体、先思路后过程、揪易错点。不跳步。范围不设限 |

### 系统课程与讲义的职责划分

| | 系统课程 | 讲义 |
|------|---------|------|
| **驱动方式** | 教材 + 课标 + 学科史 → 按章节顺序推进 | 学生需求 → 有错题讲错题，没错题推进进度 |
| **依赖学生？** | 不依赖。系统全面有深度，任何情况可用 | 完全依赖。根据学生反馈、错题、测验决定内容 |
| **内容来源** | 教材知识点 + 题型归纳 + 学科史 + 参考教辅 | 学生错题 + 参考题库优先 + 可借用系统课程 |
| **存放** | `{{科目}}/系统课程/` | `讲义/YYYY-MM-DD/` |
| **节奏** | 超前于讲义，作为"弹药库"储备 | 按学生实际进度，灵活调整 |

> 讲义可借用系统课程内容，标注清楚来源，同时把系统课程的内容写入讲义，不能只是引用跳转

  - **Wiki 知识库**（学生画像、错题、进度）

- **文件操作**：用白名单策略，避免误删已有资料
- **唯一目的**：服务好学生——所有工作流优化都围绕学生的接受度和进步

## 八、检查清单（每次任务前快速过一遍）

### 8.1 收到用户请求时

- [ ] **先读 [[{{学生目录}}/index]] 了解 vault 全貌**
- [ ] **读 [[{{学生目录}}/log]] 最后 5 条了解近期历史**
- [ ] 用户是否上传了文件？检查 Downloads 和 vault 目录
- [ ] 文件路径是否含中文？→ 用 Python 处理
- [ ] 是否需要 OCR？→ 试 2 次，不行就问
- [ ] 需求是学生版、教师版还是两者都要？
- [ ] **这个请求是否涉及诊断或查漏补缺？** → 如果是，关注学生自学的薄弱点

### 8.2 创建讲义时

- [ ] 文件名用了括号吗？→ 改用 ` · `
- [ ] frontmatter 正确吗？（tags, status, created）
- [ ] 标题是 `# `（空）吗？
- [ ] 大节之间的 `---` 删了吗？
- [ ] 教师版有定位说明吗？
- [ ] 教师版链接了学生版吗？
- [ ] **教师版每题有课堂引导语吗？**（一句口语化开场白）
- [ ] **大题规范遵守了吗？**
- [ ] **思考规范体现了？**（先分析再列式、解题路径清晰、分类讨论完整）
- [ ] **黑板体格式检查**：推导使用箭头链（→）、关键结论 `\boxed{}`、正文中没有老师不会说出口的话 → 移入 `%% 注释 %%`
- [ ] **学生版零 `>` 引用块**（铁律）
- [ ] **参考题库是否有可选题？**
- [ ] 重点题按标准格式写了吗？
- [ ] 重点题附带方法拓展了吗？
- [ ] 学生版留白够吗？（每个题 8-10 个 `<br>`）

### 8.3 删除文件时

- [ ] 确认过哪些文件要被删除？
- [ ] 白名单包含所有已有学习资料吗？
- [ ] 是否可以先打印列表让用户确认？
