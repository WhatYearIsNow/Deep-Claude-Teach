# lecture — 课前一条龙

## 🔶 前置（自动执行，不提问）

### 第一步：资料库检索（最高优先级，严禁跳过）

> ⚠️ **如果你跳过了这一步，本次产出的所有讲义内容无效。没有例外。**

1. **`ls` 列出学生专属 `参考题库/`** —— 这是选题第一参考源
2. **`ls` 列出共享教辅目录结构** —— `{{科目}}/参考教辅/`
3. **如有扫描版 PDF，按 §1.4.1 提取内容** —— PyMuPDF 渲染 PNG → `node vision.js` 读取
4. **确定本次可选题目清单** —— 按优先级：用户指名 > 专属题库 > 共享教辅 > 系统课程 > 自编

> 🔔 **做完以上 4 步后，继续执行下面的共享清单。**

### 第二步：执行共享前置清单

5. 读 `CLAUDE.md` → 确定科目（路径含 `物理-` → 物理 / `数学-` → 数学）
6. 按 [[.claude/shared/workflow]] §〇 执行必读项：
   - 读 workflow §七（偏好+家长要求）+ §八（检查清单）+ §九（教学沉淀）
   - 读学生 `index.md` + `log.md` 最近 5 条
   - 读 `wiki/学生/` 画像 + `wiki/进度/课程进度`

### 第三步：作业与家长反馈

7. 如有 `作业/` 目录 → 逐图 `node vision.js` 读取，对比上份讲义，标记对错
8. 如有本次课日期文件夹下的家长微信截图 → `node vision.js` 识读，提取关切，作为选题和风格调整依据

## 🟡 交互确认（只问库里没有的）

> **前置已自动读取**：学生画像、家长要求、课程进度、上次简报、作业批改——这些全在 vault 里，不需要问。
> **Skill 只问两件事**：① 用户没明说时，确认学生和主题；② 有没有今天才出现的临时要求。

### 选题来源判定

```
用户消息中指明了资料？
  ├─ 是（如"用必刷100讲出函数讲义""用百年真题选题"）
  │   → 🔶 该资料为第一优先级，跳过默认检索顺序
  │   → 直接从指名的资料中选题
  └─ 否 → 按默认顺序：专属题库 → 共享教辅 → 系统课程 → 自编
```

### 流程

1. 用户消息里有的 → 直接用
2. 用户没说但库里有的 → 前置已读，直接用
3. 用户没说、库里也没有的 → 问（通常只需问：学生？主题？临时要求？）
4. 汇总确认 → 生成

### 格式

用 `AskUserQuestion`，点击选择。

## 🟡 执行 · 生成讲义

> 🔔 **强制性检查点：在开始生成之前，你必须先输出以下内容：**
>
> ```
> 📋 本次选题来源报告：
> - 用户指名资料：[有/无，若有列出]
> - 学生专属题库：[ls 结果，列出可用文件]
> - 共享教辅：[ls 结果，列出可用目录/PDF]
> - 系统课程：[是否有相关章节]
> - 最终选定来源：[具体说明用哪个资料]
> ```
>
> **必须先输出这个报告，再开始生成讲义。不输出报告 = 跳过了资料库检索 = 产出无效。**

### 讲义结构

```
Part 1 · 课前回顾（5-8 min）
  → 作业错题讲评 + 方法纠偏
  → 只有存在作业/上次课遗留问题时才有此部分

Part 2 · 新内容（主体）
  → 选题优先级：学生专属参考题库 → 共享参考教辅 → 自编
  → 来源标注：教师版必标，学生版只标专属题库
```

### 学生版铁律
- 零 `> ` 引用块、零 AI 向 meta
- 题目 + 充足留白（`<br>` 8-10 个）
- 课前回顾部分的题目重现在学生版

### 教师版铁律
- 对照学生版生成，口语化黑板体
- 箭头链推导、先思路后过程、揭易错点
- 所有计算不跳步
- 每道题课堂引导语 + ⚠️ 陷阱预警
- 关键结论 `\boxed{}`
- 答案必核对：对照 PDF 参考答案
