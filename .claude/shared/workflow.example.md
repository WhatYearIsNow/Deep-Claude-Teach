# 家教 Vault 共享工作流

> **定位**：物理、数学两科通用的操作规范。各科 workflow 引用此文件，只保留科目特有内容。
> **Skill 定义**：见 [[CLAUDE.md]] 快捷指令表。本文档是 Skill 执行时的参考手册。

## 一、核心工作原则

### 1.1 黄金法则：先问，别死磕

> 🔴 **作业红框 = 必讲点**：教师批改时用红色方框圈出的位置是学生解答出错点。备课和讲课时，这些红框是核心切入点——重复错误、概念混淆、跳步漏步，每个红框背后都有一个需要纠正的思维惯性。教师版每题至少回看一次对应作业红框，确保课堂纠正全覆盖。

| 场景 | 旧行为 | 新行为 |
|------|--------|--------|
| 扫描件/手写体 OCR | 连续尝试 10+ 种方案 | 尝试 2 次后仍不佳 → 请用户上传文字版或 clean PDF |
| 文件路径含中文报错 | 花时间调试编码 | 改用 PowerShell 或 Python subprocess + env |

### 1.2 省 token 优先级

```
用户提供 clean text > 用户上传 clean PDF > OCR clean PDF > OCR 手写体
```

**结论**：遇到手写扫描件，最多试 2 轮 OCR，不行就开口要文字版。

### 1.3 文件安全

- 删除前列出所有待删文件，确认不包含已有资料
- 推荐用白名单（列出要保留的）而非黑名单
- 误删后从聊天记录（JSONL transcript）搜索 Write tool 调用恢复

### 1.4 资料库优先（强制）

> ⚠️ **出题/选题前，必须先检索资料库。库里有的直接用，禁止自己编造题目。**

**选题检索顺序**（逐级递减，上一级有就不往下）：

```
⓪ 用户指名资源          ← 🔴 最高优先级。用户说"用XX出题"，XX 就是唯一来源，跳过其他
① 学生专属参考题库/     ← 该学生错过的题、学校试卷、卓越班专题
② 共享参考教辅           ← 必刷100讲 + 高考核心40卷 + 百年真题 + 集英苑
③ 系统课程              ← 数学/系统课程/ 或 物理/系统课程/（已有讲义可借用）
④ 自编                  ← 仅当前四级都没有合适题目时，才自己出题
```

**共享资料库目录**：

| 路径 | 内容 | 用途 |
|:---|:---|:---|
| `数学/参考教辅/【2026版】必刷100讲常规版/` | 按章节组织（第1-12章），每章含多个模块 PDF | 系统课程依据、讲义选题第二参考 |
| `数学/参考教辅/高考数学核心40卷/` | 40 套模拟卷 + 详解答案 + 44个常用结论 | 综合练习、模拟考试选题 |
| `数学/参考教辅/集英苑19题讲义.pdf` | 集英苑专题讲义 | 专题突破 |
| `数学/高考试卷/【百年真题】1917-2024年高考数学真题2.0 (1).pdf` | 百年高考真题汇编 | 真题训练 |
| `数学/高中教材/` | 人教版必修+选择性必修全套 + 课程标准 | 知识点对照 |

> ⚠️ **关键事实：以上所有 PDF 均为扫描图片版，没有任何文字层。pdftotext / PyMuPDF get_text 全部无效。唯一提取方式见 §1.4.1。**

### 1.4.1 扫描版 PDF 提取——唯一可行方法

> 🔴 **铁律：所有参考教辅 PDF 必须走此流程。pdftotext 返回空/乱码 ≠ 无法提取，只是方法不对。**

**三步提取法**：

```bash
# 步骤 1：PyMuPDF 渲染 PDF 页面为 PNG
python -c "
import fitz
doc = fitz.open('目标文件.pdf')
print(f'总页数: {doc.page_count}')
# 渲染前 3 页，判断结构（通常第 1 页是封面/空白，第 2-3 页是内容）
for i in range(min(3, doc.page_count)):
    pix = doc[i].get_pixmap(dpi=150)
    pix.save(f'_p{i}.png')
    print(f'Page {i+1}: {pix.width}x{pix.height}')
"

# 步骤 2：vision.js 读取页面内容
node vision.js "_p1.png" "列出这一页的所有文字内容，包括标题、题目编号、题目正文、公式。不要漏掉任何文字。"

# 步骤 3：根据 vision 返回的内容，确定选题范围，然后渲染对应页面
python -c "
import fitz
doc = fitz.open('目标文件.pdf')
for i in [3, 4, 5]:  # 需要具体的页码范围
    doc[i].get_pixmap(dpi=150).save(f'_p{i}.png')
"
```

**必刷100讲特殊结构**：
```
【2026版】必刷100讲常规版/
  └── 第X章 XXX/
      └── 模块N：XXX/
          ├── 第N节 XXX（方法册+习题册）.pdf    ← 题目+知识点讲解
          └── 第N节 XXX（习题册+答案册）.pdf    ← 答案
```

**执行要求**：
- 用户指名资料（如"用必刷100讲出函数讲义"）→ 该资料为唯一来源，直接从中选题
- 用户未指名 → 先 `ls` 列出目录结构，再按主题定位到具体 PDF，渲染 + vision.js 读取
- **严禁**：看都不看资料库，凭记忆或想象直接编题
- **严禁**：pdftotext 返回空就放弃——那只是说明它是扫描版，不是无法提取

## 二、文件命名与格式规范

### 2.1 命名规则

```
[主题] · [版本标识].md
```

- **禁止**：圆括号 `（）`、方括号 `[]`
- **采用**：` · `（中文全角点 + 空格）
- **示例**：`运动学 1 直线运动 学生版.md` ✅　`运动学 1 直线运动（学生版）.md` ❌

### 2.2 标题与分隔线

| 元素 | 规则 |
|------|------|
| 文档标题 | `# `（空一格，不写文字——导出时隐藏标题） |
| 一级标题 | `# 第一部分：XXX` |
| 分隔线 `---` | 仅用于同一大节内部的区块分隔 |
| 大节之间 | 不要加 `---`（如 `# 第一部分` 和 `# 第二部分` 之间不加） |

### 2.3 文件头 frontmatter

```yaml
---
tags:
  - 讲义/物理        # 或 讲义/数学 / 系统课程/物理
  - [专题]
  - 学生版            # 或 教师版
status: v1
created: 2026-05-02
---
```

### 2.4 格式约定

- **公式**：LaTeX `$...$`（行内）或 `$$...$$`（块级）
- **关键结论**：`\boxed{...}`
- **wikilink**：内部 `[[Note]]`，外部 `[text](url)`
- **教师版**：标注定位 `> **定位**：...`、链接学生版 `> **配套学生版**：[[XXX 学生版]]`
- **各科特有格式规范**见各科 workflow §九

## 三、学生版 / 教师版铁律

### 3.1 学生版

**禁止出现**：`> **定位**` `> **来源**` `> **依据**` `> 📎` `> 🎤` `⏱` `★★★` `%%注释%%` `> **目标**` `> **开场**` `> **方法核心**` `> [!TIP]`

**允许**：`> ⚠️` 陷阱提醒、`> 💡` 理解技巧——这是给学生的内容，不是 AI meta。

**额外禁止**：
- 完整解题过程（推导、列方程、求解——这些是教师版内容）
- ` ``` ` 代码块（箭头链、ASCII 图用自然语言或表格替代）
- `见教师版详解`、`参考 XX 讲义`——学生手里只有学生版
- 方法总结表、方法地图等教师参考材料

**来源标注**：题库题标 `【物理50题】-第X题` 或 `【高考】XXXX卷`——写在题目标题中。**自编题不标注任何来源**，不加 `【自编】` 标签，直接写题目正文。

**标题层级**：
```
# （空标题）
## 第X部分：XXX（大部分）
### 【物理50题】-第X题 或 ### 【高考】XXXX卷（题库题）
### 方法X：XXX（方法说明）
自编题不加 ### 标题，直接正文
```

### 3.2 教师版

**风格**：口语化（"咱""你看""很多同学到这就不行了"）、先思路后过程、陷阱优先（每题至少一个常见错误）、充要替换视角（⇔ vs ⇒）

**每道题必备元素**：
| 元素 | 格式 | 用途 |
|:---|:---|:---|
| 课堂引导语 | `> 🎤 "..."` | 每道题/步骤一句口语化开场 |
| 陷阱预警 | `> ⚠️ ...` | 标注容易出错的地方 |
| 受力/分析表格 | Markdown 表格 | 每个量：方向 + 大小 + 符号 |
| 解法思路 | `> 🎤 **解法思路**：...` | 教老师如何引导 |
| 教师自查 | `%% ... %%` | 推导出错时从哪里检查 |

**禁止行为**：
| ❌ | ✅ |
|:---|:---|
| "联立消去……可解得……" | 每步代入、合并系数写出来 |
| 方程只写结果不写中间 | 每步展开（如 $N_B = N_{AB} + 2mg\cos45^\circ = \cdots = \frac{3\sqrt{2}}{2}mg$） |
| 摩擦方向直接给结论 | Step 0 先判断滑动趋势 |
| 不写解法思路 | 单独一段讲"先消谁、为什么" |

**解题标准格式（物理）**：字母公式 → 代入数值 → 结果，三步分离，禁用 $\times$

**解题标准格式（数学）**：解 → 设 → 列 → 解 → 答，五步完整

## 四、双讲义输出流程

### 4.1 核心要求

| 版本 | 用途 | 内容特点 |
|------|------|---------|
| **学生版** | 打印给学生做题 | 题目 + 大量留白（`<br>`） |
| **教师版** | 老师上课看着讲的讲稿 | 题目 + 详细解析 + 方法拓展（口语化、可讲性强） |

### 4.2 题目层次分配

| 优先级 | 覆盖深度 | 适用 |
|--------|---------|------|
| **重点题** | 完整规范解答 + 方法拓展 | 学生需要规范过程的题 |
| **普通题** | 简要方法点拨 + 答案 | 带一下即可的题 |

### 4.3 方法拓展格式

至少覆盖 2-3 种方法：
- 常规法（学生容易想到的）
- 巧解法（省时间的）
- 验证法（图像法/相对运动法等）

巧解标注"⏱ 1%"和适用条件，呈现顺序：通法在前，巧解在后。

## 五、文件处理

### 5.1 PDF 读取

```bash
# 全文（首选）
pdftotext -layout "file.pdf" -

# 指定页
pdftotext -f 1 -l 5 -layout "file.pdf" -

# 逐页分析
python -c "
import fitz
doc = fitz.open('file.pdf')
for i in range(doc.page_count):
    text = doc[i].get_text()
    if text.strip():
        print(f'===== PAGE {i+1} =====')
        print(text[:500])
"
```

### 5.2 提取图片

**从 PDF 提取嵌入图（首选）**：用 `doc.extract_image()` 直取嵌入位图。**禁止 canvas 猜坐标裁剪。**

```python
import fitz
doc = fitz.open("题库.pdf")
page = doc[page_index]  # 0-indexed

# 1. 找到题目文字 y 坐标
blocks = page.get_text('blocks')
q_y = next(b[1] for b in blocks if 'XX．' in b[4][:10])

# 2. 找离题目最近的嵌入图
infos = page.get_image_info()
imgs = page.get_images(full=True)
closest = min(zip(infos, imgs),
    key=lambda x: min(abs(x[0]['bbox'][1]-q_y), abs(x[0]['bbox'][3]-q_y)))

# 3. 直接提取
info, img = closest
xref = img[0]
base = doc.extract_image(xref)
with open(f'{题号}.png', 'wb') as f:
    f.write(base['image'])
```

**PDF 页转图片**：Node.js `pdf-to-img`（npm），页面从 0 开始计数。

### 5.3 图片处理——铁律：禁止 Read，直接选对工具

> ⚠️ **Read 工具不支持图片。不要试，一次都别试。看到图片文件直接按下面决策树选工具。**

```
图片文件 (.png / .jpg / .webp / .jpeg)
  │
  ├─ 需要"看懂内容"（题目截图、手写讲稿、图表理解）
  │   → node vision.js "<路径>" "用中文描述这张图片"
  │
  ├─ 需要"提取文字"（纯 OCR，不需要理解）
  │   → rapidocr_onnxruntime
  │
  └─ PDF 里的嵌入图
      → PyMuPDF extract_image() 直提 → vision.js 确认归属（§5.4.2）
```

**rapidocr 用法**：
```bash
python -c "
import sys, io
sys.stdout = io.TextIOWrapper(sys.stdout.buffer, encoding='utf-8')
from rapidocr_onnxruntime import RapidOCR
engine = RapidOCR()
result, _ = engine('image.png')
for box, text, score in result:
    print(text)
"
```

### 5.4 图片格式转换

```powershell
Add-Type -AssemblyName System.Drawing
$img = [System.Drawing.Image]::FromFile('input.png')
$img.Save('output.jpg', [System.Drawing.Imaging.ImageFormat]::Jpeg)
$img.Dispose()
```

### 5.4.1 识图（千问 VL Max）

> 基础模型无原生识图能力。遇到需要理解图片内容时，不要用 Read 工具（返回 `[Unsupported Image]`），改用 `vision.js`。

```
node vision.js "<图片路径>" "用中文描述这张图片"
```

| 项 | 说明 |
|:---|:---|
| 模型 | `qwen-vl-max`（千问 VL Max），DashScope API |
| 图片位置 | Obsidian 粘贴的图片在 `attachment/` 目录 |
| 适用场景 | 题目截图、PDF 页面截图、手写讲稿、板书照片 |
| 不支持 | 直接 OCR 提取文字（用 §5.3 rapidocr）；图片理解/描述用 vision.js |

#### 5.4.2 从 PDF 提取单个题目配图

> **核心发现**：大多数试卷和教辅 PDF 将配图作为嵌入图存储，PyMuPDF 可直接提取，**无需渲染+裁切**。千问只用来确认"哪个图是哪道题的"。

##### 方法 A：嵌入图提取（首选）

适用：试卷、必刷100讲等大多数 PDF。

```python
import fitz
doc = fitz.open("试卷.pdf")

# 找到题目所在页 → 提取该页所有嵌入图
page = doc[page_index]  # 0-indexed
for j, img in enumerate(page.get_images(full=True)):
    xref = img[0]
    base = doc.extract_image(xref)
    ext = base['ext']
    fname = f"_img{j}.{ext}"
    with open(fname, 'wb') as f:
        f.write(base['image'])
    print(f"{fname}: {base['width']}x{base['height']}")

# 千问确认归属：
# node vision.js "_img0.png" "这是第X题的图吗？描述内容。是/否。"
```

##### 方法 B：渲染+裁切（备选）

适用：全页扫描 PDF，无独立嵌入图。

```python
page = doc[page_index]
pix = page.get_pixmap(dpi=200)
pix.save("_page.png")

# node vision.js "_page.png" "找出题X的图，给像素坐标(x1,y1,x2,y2)。页面WxH。"
# 坐标加 20% padding 后 Pillow crop
```

##### 实测记录

| PDF | 方法 | 结果 |
|:---|:---|:---|
| {{学校}}高一期末数学 | A（嵌入图） | 2 张 441×272 JPEG，千问秒确认 |
| 卓越班物理前三章 | A（嵌入图） | 4 张 PNG，千问确认题9 为 x-t 图 |

> ⚠️ **优先试方法 A**。只有 `page.get_images()` 返回空时才用方法 B。

## 六、踩坑速查

| 坑 | 原因 | 正确做法 |
|:---|:---|:---|
| **pdftotext 返回空/乱码就说"无法提取"** | 参考教辅全是扫描图片版 PDF，无文字层 | **不是无法提取，是方法不对。** 改用 PyMuPDF 渲染 PNG → vision.js 读取（§1.4.1） |
| `Read` PNG/JPG → 浪费 token | 模型不支持图片 | **禁止 Read 工具读图**。内容理解用 `node vision.js`，文字提取用 rapidocr |
| 不看资料库就编题 | 图省事凭记忆 | 出题前必查：专属题库 → 共享教辅 → 系统课程，三级检索 |
| `Read` PDF → `[Unsupported]` | Read 不支持 PDF | 用 `pdftotext` 或 PyMuPDF |
| canvas 猜坐标裁图 | 大半页文字当图交 | `doc.extract_image()` 直取嵌入图 |
| 给一堆候选图让用户挑 | 没做筛选 | 用题目文字 y 坐标定位最近嵌入图 |
| Python 中文输出乱码 | stdout 默认 GBK | `sys.stdout = io.TextIOWrapper(sys.stdout.buffer, encoding='utf-8')` |
| `npm install -g` 后 `require` 找不到 | 全局包 CJS 路径漂移 | 临时目录 `npm init -y && npm install xxx` 再用 |
| `pdftoppm` 不存在 | mingw64 只装了 pdftotext | 提取图片用 `pdf-to-img`（npm） |
| ImageMagick 不存在 | 系统没装 | PowerShell .NET 做格式转换 |
| B 站 API 返回 412 | 需要 WBI 签名 | 用 Python WBI 签名脚本 |
| 一数老视频无 AI 字幕 | 2023 年前未启用 | Clipper 插件或找新版替代 |
| 讲义图片不显示 | wikilink 路径错 / 文件名重复 | `images/` 子目录 + 唯一文件名 `![[xxx.png]]` |
| 教师版"联立可得"讲课卡壳 | 推导跳步 | 每步代数写出；受力表格化；摩擦方向先判断趋势 |

├── wiki/
│   ├── 学生/         ← 学生画像
│   ├── 概念/         ← 核心概念页
│   ├── 方法/         ← 解题框架/策略
│   ├── 错题/         ← 按知识点组织
│   └── 进度/         ← 学期进度总览
├── 讲义/             ← 按日期子文件夹
├── 系统课程/          ← 知识驱动（含 .claude-workflow.md）
└── 参考题库/          ← 原始资料（不可变）
```

### 8.2 Wiki 页面编写规范

```yaml
---
tags:
  - wiki/类型    # wiki/概念, wiki/方法, wiki/学生, wiki/错题, wiki/进度
status: v1
created: 2026-04-27
updated: 2026-04-27
---
```

- **持久积累**：更新是"丰富"而非"覆盖"
- **交叉引用**：末尾必须有"关联文件"章节，wikilink 格式
- **来源标注**：每个关键信息标注来源
- **可扫描性**：善用表格、列表

### 8.6 Ingest 标准流程

```
收到新资料
  ├─ 原始资料（PDF/题库）→ 存放对应 raw 目录，不改动
  ├─ 逐字稿 → 读 → 生成课程简报 + 课程反馈 → 更新手册 §九
  └─ 其他 →
       1. 读资料，理解核心内容
       2. 更新 Wiki：新概念/方法/学生表现/进度
       3. 追加 log
       4. 更新 index
       5. 有易错点 → 更新错题/index
```

### 8.7 逐字稿处理闭环

```
用户上传逐字稿
  → 定位对应教师版讲义（同日期文件夹）
  → 先读教师版讲义，建立"参考答案"框架（题目顺序、关键公式、🎤引导语、⚠️陷阱）
  → 对照讲义读逐字稿：
       - 题目顺序 → 定位逐字稿当前在讲哪道题
       - 关键公式 → 识别被 OCR/语音转写毁掉的公式
       - 🎤引导语 → 定位师生对话分界点
       - ⚠️陷阱 → 预判学生卡点
  → 提炼：学生反馈 / 教学亮点 / 踩坑记录
  → 生成课程简报（存入日期子文件夹）
  → 生成课程反馈（存入日期子文件夹，纯文本格式，发给家长/学生）
  → 更新 wiki/学生 + wiki/错题 + wiki/进度
  → 追加 log + 更新 index
  → 更新 workflow §九（新教学沉淀）
```

**简报必含**：课程概览、课堂实况（每题耗时+学生反应）、重要教学成果、学生状态分析、工作流优化建议、下次课预告。

**反馈必含**：上课时间、上课内容、上课效果、发现的问题/薄弱环节、下次课预告。**纯文本格式**，无任何 markdown 符号，直接复制粘贴到微信/QQ 发送。

### 8.8 Lint 健康检查

**触发**：用户要求 / 每 3-4 次课后自动一次。

**检查项**：
- 概念覆盖：最近接触的知识点是否有对应 Wiki 页？
- 信息过时：学生偏好变化是否已同步？
- 矛盾检测：不同页面之间是否有矛盾？
- 孤岛页面：没有 inbound links 的页面
- index 准确性：链接全部有效？
- 文件规范：新文件是否遵循命名规则？

## 九、讲义制作工作流

### 9.0 课前准备：家长反馈

> 每节课后家长会发反馈（聊天截图），存放约定：

- **存放位置**：直接扔进本次讲义文件夹 `讲义/MMDD/`，与讲义并列
- **处理方式**：`lecture` Skill 前置阶段自动用 `node vision.js` 逐张识读
- **提取内容**：薄弱点 / 表扬 / 投诉 / 新要求 → 作为选题和风格调整依据
- **文件名**：不做强制要求（`家长反馈.png`、`家长反馈2.png` ... 均可，vision.js 都能读）

### 9.1 阶段 1：选题

- 从参考题库 PDF 选定题目，记录 PDF 题号、原格式（单选/多选/解答）
- **逐字记录 PDF 原文字**，不改写
- **选题时对照家长反馈提取的关切**，优先覆盖薄弱点
- 自编题不标注来源

### 9.2 阶段 2：截图

用 `doc.extract_image()` 直取嵌入图（见 §5.2）。严禁 canvas 猜坐标、给一堆候选让用户挑、截图包含题目文字。

### 9.3 阶段 3：编写学生版

- 每题开头标注来源：`【物理50题】-第X题` 或 `【高考】`。自编题不标
- 题目正文使用 PDF 原文字，逐字照搬
- 不把选择题拆成分步计算小问（除非用户明确要求）
- 图片嵌入 `![[images/xxx.png]]`
- 零 `>` 引用块（见 §3.1）

### 9.4 阶段 4：编写教师版

- 题目格式与学生版完全一致
- 解答完成后**必须与 PDF 参考答案逐题核对**（阶段 5）
- 核对项目：选项字母、数值、方向、单位、范围
- 不一致 → 以 PDF 答案为准，重新检查推导
- 修正处标注 `%% vX 错误：……已修正 %%`

### 9.5 阶段 5：答案核对（强制步骤，不可跳过）

1. 提取 PDF 末尾参考答案表，完整列出
2. 逐题对比学生版答案与 PDF 答案
3. 逐题对比教师版解答结论与 PDF 答案
4. 标记所有不一致 → 修正 → 再核对一轮

> PDF 参考答案是权威来源。推导→核对→不一致就反查推导→修正→再核对。

### 9.6 常见错误清单

| # | 错误 | 正确 |
|:--:|:---|:---|
| 1 | 擅自改写格式（选择题拆成计算步骤） | 保持原格式 |
| 2 | 改写题目文字 | 逐字照搬 PDF 原文 |
| 3 | 忘记标注来源 | 每题必标 |
| 4 | canvas 猜坐标裁图 | `doc.extract_image()` 直取 |
| 5 | 不核对答案 | 阶段 5 强制 |
| 6 | 摩擦力方向搞混 | 牛顿第三定律检查 |
| 7 | 弹簧方向搞反 | 先算长度 vs 原长 |
| 8 | 推导自洽但答案错 | 以 PDF 答案为准反查 |
| 9 | 给一堆候选图 | 文字 y 坐标定位，只给最近那张 |

## 十、试课教训速查

| # | 教训 | 行动项 |
|:--:|:---|:---|
| 1 | **开课前必须确认学校进度**——什么已经讲了、什么还没讲 | 首次课前置：收集学生近期试卷 + 学校教学进度 |
| 2 | **学生驱动的选题 > 老师预设的选题** | 开课时先让学生指出最需要讲的题目和知识点 |
| 3 | **首次课不要单独讲方法论**——先解决一个具体问题建立信任 | 方法论渗透到讲题中，不单独占用时间 |
| 4 | **扩展前必须征求同意**——"要不要我找一道类似的题给你试试？" | 永远先问再展开 |
| 5 | **错题≠需要重讲**——学校讲过的错题需要变式，不是重复讲解 | 错题→同类题变式 |
| 6 | **老师匹配要考虑年龄感和学生偏好** | 首次课前了解学生对老师风格的期望 |
